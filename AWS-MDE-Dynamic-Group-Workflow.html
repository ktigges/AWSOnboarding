Problem

How do we target AWS servers with Microsoft security policy?

  • Microsoft Entra dynamic groups can use properties stored on an Entra device record.
  • Azure devices already have useful properties in Entra that can be used for automatic grouping.
  • AWS servers can be onboarded to Microsoft Defender, but Entra does not know their AWS account or AWS platform label.
  • The MDE device tag is visible in Defender, but an Entra dynamic group cannot evaluate it directly.
  • Result: Entra needs an AWS-specific value on the device record before it can place the server in the correct policy group.

End-to-end steps

Solution workflow

Tag on ProvisioningAWS provisioning writes the account-and-platform tag into the device's MDE configuration.
Report to MDEThe tag is ingested into MDE when onboarded.
Map Tag to Entra AttributeThe scheduled Function finds the device and fills extensionAttribute1.
Dynamic Group EvaluationEntra dynamic membership matches the extension attribute value.
Apply policyIntune targets the resulting group through MDE Security Settings Management.

The values shown are only the tags selected for this test. Use any naming scheme that fits your environment, and configure multiple allowed tag values and dynamic groups for different device populations or policy requirements.

AWS provisioning

Requirements

Inputs

  • AWS account and region access
  • MDE onboarding packages for Linux and Windows
  • Un-onboarded Linux AMI with MDE installed
  • Windows administrator RSA public key
  • Platform suffixes: linux-lab and windows-lab

Provisioning performs

  • Creates EC2, S3, IAM, security group, and SSM resources
  • Builds the tag from AWS account ID plus platform suffix
  • Writes the tag into local MDE configuration
  • Applies the local Defender baseline and bootstrap exclusion
  • Onboards the server to MDE and verifies service health

Tags used in this lab build: <aws-account-id>-linux-lab and <aws-account-id>-windows-lab

Middleware

Tag worker

  • Runs every five minutes in this demo; the schedule is configurable.
  • Queries MDE Advanced Hunting for the latest record for every Linux and Windows Server endpoint.
  • MDE does not provide an “AWS machine” category in this query. The worker identifies AWS devices by matching RegistryDeviceTag against the configured allow-list.
  • Matches the MDE device to one Entra device, preferably by AadDeviceId.
  • Writes the MDE tag to extensionAttribute1 when the field is blank or does not match.
  • Does nothing when the correct value is already present or the device match is uncertain.
DeviceInfo
| where OSPlatform contains "Linux" or OSPlatform startswith "WindowsServer"
| summarize arg_max(Timestamp, *) by DeviceId
| project DeviceName, AadDeviceId, OSPlatform, RegistryDeviceTag

Worker filter example:
RegistryDeviceTag in ("<aws-account-id>-linux-lab", "<aws-account-id>-windows-lab")

Timing

Timing steps

  • Device setup: SSM writes the local tag and completes MDE onboarding.
  • MDE reporting: the device must send a current record containing the tag.
  • Function schedule: the next job runs within the five-minute interval after MDE has the tag.
  • Group evaluation: Entra processes the updated extensionAttribute1.
  • Policy processing: Intune evaluates the assignment and the device receives the policy through MDE.

Each service processes its step independently. Windows may also complete one reboot before its tag is reported.

Policy assignment

Attach policy to the Entra dynamic groups

Entra group rules

  • Linux: device.extensionAttribute1 -eq "<aws-account-id>-linux-lab"
  • Windows: device.extensionAttribute1 -eq "<aws-account-id>-windows-lab"
  • Use Security groups with Dynamic Device membership.

Policy setup

  • Enable MDE Security Settings Management for Linux and Windows Server.
  • Enable MDE enforcement of endpoint security configurations in Intune.
  • Create the appropriate Linux or Windows endpoint security policy.
  • Assign each policy to its corresponding Entra dynamic group.

Verify in order: local tag → MDE record → Entra attribute → dynamic group → policy status → effective device settings.
